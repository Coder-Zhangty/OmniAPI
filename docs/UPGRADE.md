# 升级与回滚

1. 阅读目标版本官方 Release、数据库迁移说明及安全公告，核查许可证变化。不要自动升级到 RC / nightly。
2. 运行健康检查和备份，保存当前 `images.lock.json` 与 `.env`。确认备份 manifest 完整并已有隔离恢复证据。
3. 在独立项目先测试目标版本。明确修改镜像版本来源，重新解析并锁定摘要；不能只把 `latest` 写入生产。
4. 在维护窗口停止接入，部署已测试目标镜像。复验登录、模型、普通调用、SSE、鉴权、日志、扣额、持久化及备份。
5. 失败时停止新流量，用升级前备份恢复到新卷，再启动旧摘要镜像。数据库经过迁移时不允许只降级应用镜像继续使用新数据库。

当前 `lock-images` 保留已有摘要，不会暗中刷新版本。需要升级时，应在部署项目的新分支明确更新来源和锁文件，再测试；不要覆盖仅有的升级前备份。

`v0.13.2` 是本项目批准的稳定版基线，并不等于所有后续安全问题都已修复。发布公网服务前必须复核官方安全公告和维护状态；此交付默认仅回环访问。
